逐篇结果见 [语境回归报告](../research/qwen-context-scope-regression-report.json)。所有原文、QA、请求响应和图谱保留在忽略目录及用户授权的 Google 项目文件夹，不能提交 Git。

## 下一轮实施顺序

1. 实现 v10：主体与语境首阶段 → 完整来源/契约校验 → 冻结语境 → 串行逐语境子抽取 → 整篇最终验收。
2. 为越界证据、外部主体 ID、重复位置、首阶段失败不继续、子阶段失败不发布半篇、离线回放篡改添加回归测试。
3. 先在固定失败来源重新抽取，完整 36 篇来源分母不变；记录每阶段请求、使用量、失败和覆盖，不提前扩量。
4. 成功候选仍只具备来源与工程保证。语境分类、参与角色、遗漏等语义风险仍需独立评估，不以 Schema 限制证明法律正确性。

实施状态：v10 分阶段协议、逐阶段服务负载与预算、原始 RPC 账本及整篇拒收已实现；离线回放会重建每个请求并逐字比较中间产物、候选和状态。v10 的 Spark4396…真实首阶段返回完整 JSON（2672 输出 tokens、113.918 秒），但两处姓名不在指定片段，整篇拒收，子阶段零调用；失败和零调用回放保持一致。这一新试验是0/1，不能改写原v8结果。进一步设计v11：首阶段每主体一条真实身份锚点，其他Mention在当前语境内抽取，保留锚点且禁止重复坐标；不是删提及换通过。v11 真实试跑1次55.878秒，身份锚点逐字来源检查通过，但quoted_material子语境的10个片段完全不在声明的父语境内，完整契约拒收，子阶段零调用。草稿没有另一个包含它的父语境，不能通过换一个父ID解决。两轮均0/1整篇接受，累计2次请求169.797秒；两轮失败均零调用回放一致。语境生成最多 32 个，属于请求预算限制而非完整语义覆盖证明；未归入语境的原文片段 ID 单独记录。默认 v5 与历史运行不变；新候选不自动载入 Neo4j。


## 新反馈：父语境覆盖与直接断言范围需要分开

v11 的父语境只包含引述前的法院叙述，引用材料被分成子语境，父覆盖没有包围子引用。这暴露出“父语境覆盖原文”与“法院自己的断言证据”混在同一个字段的设计歧义。不能自动扩大已保存父语境来换通过，也不能把引述事实复制进法院事件；当前完整拒收正确。

下一轮优先版本化区分包围范围和直接断言范围：由新首轮明确声明嵌套引用，父覆盖包含子语境，但父阶段的可断言证据不得自动继承子引用。先分别测试结构包含、引用不提升、证据守恒和失败回放，再重抽同一篇；026b/442c及扩量排在其后。该表示尚未实现，不能说已解决父子语境问题。


## 契约0.3 / v12实施

已实现[包围范围与直接断言来源](scoped-contexts.md)：新增assertion_evidence，要求父子包围包含、直接来源与子范围隔离、范围分配守恒；事件/角色/属性不能借用子引用。图中covers与assertion_source分别投影并无损还原。v12首阶段显式生成enclosing_units/assertion_units，完整校验后冻结，子阶段只接收直接片段和对应Schema枚举。旧0.2记录与v11失败不迁移、不自动扩大。代码和回归已接入，真实同篇试跑待完成。

v12真实反馈已进入下一设计：分离包围/直接范围使同篇头部首次通过，但子阶段3条重复身份锚点仍造成整篇拒收。v13改为“已验证提及目录 + 完全一致复用回执 + 新位置严格校验”，原响应不可变，不以类别/位置近似合并。对court_finding直接范围内的当事人报告用语新增只读提示，结构覆盖不等于归属正确；实际整篇新结果另报。

真实v13越过重复锚点失败点：前2子语境通过、1条精确复用回执，但第三子语境仍有quote_missing_in_unit。其文字在当前直接范围有6个原文位置选项；“文字与片段ID都让模型自由生成”仍是不稳定接口，下一步应改为冻结位置目录或显式有界选择，不能默认最近/第一次。两个直接认定中的当事人报告用语提示也仍在，头部结构合法不等于法律归属正确。完整结果见research/qwen-scoped-context-report.json；两轮均0整篇接受，不扩大样本。
