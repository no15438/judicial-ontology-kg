# 未知成员集合称谓：v39 失败后的设计约束

状态：设计待实现，未计入 v39 的冻结运行，不修改本轮接受标准。

## 已确认的接口缺口

`next-flash-two-v39-01` 的 442c 已通过前 10/14 个语境，在第 11 个语境的 Mention 阶段拒收。返回中一个有精确原文位置的集合称谓被判未决，对应绑定为空；现有 Schema 要求非空的具体 Actor 绑定。该失败保留，不能删除空绑定后冒称已处理，也不能把集合自动展开为全文所有已知当事人。

已有 `existing_group` 仅表示一个提及同时指向若干可确定的既有 Actor；它不能表示集合存在而成员未明确的情形。Object 通道针对项目、平台、文书等非主体对象，也不能代替主体集合。

## 拟议表示

采用显式 CollectiveReferent / CollectiveMention，区分集合指代成立与成员身份可确定。原文证据跨度、文书、直接语境均必须保留。成员状态至少区分 `unknown`、`partial`、`explicit`；unknown 的成员列表必须为空，partial 不可宣称穷尽，explicit 仍是有证据的模型候选而非专家核验。

集合标识只在当前文书和有证据的语境内有效。同称谓不自动跨语境合并；跨出现的同一集合判断需要单独证据与决策记录。成员边必须各自有证据；不能仅根据案件头部参与者列表推导成员。

事件与陈述可指向集合，但不得自动传播到任意成员。否定、情态、说话者及法院认定范围沿用现有约束。集合不能被当作法院来满足 court_finding 的归属要求。集合内部成员未知，不等同于事件或说话者也可未知；这些字段仍分别判断。

## 工程顺序

1. 新版本契约：集合、集合提及、带证据的成员关系及事件引用；老契约和历史结果保持可回放。同步实现校验、无损装配、拒收与未决统计，不能只扩一个分类标签。
2. 冻结前发现：从原文识别可能的集合称谓及精确位置。正文首次发现时走有界补充发现和重新校验，不允许生成不存在的 Actor ID。
3. 分别决定指代存在、成员证据和事件绑定。对真正不确定的集合指代仍拒收；对于明确集合但成员未知，保留 unknown 而非强迫推测。
4. 针对未知成员、部分成员、明确成员、同称谓不同集合、非集合词组、否定事件和法院归属冲突做回归测试。语义例子仅作接口元数据测试，不伪造真实案件评测。
5. 用本次真实失败阶段做有界诊断；诊断与整篇首轮分开。再冻结两篇完整原文重新抽取，禁止历史响应复用或手动改图；通过后追加 Spark 回归，再决定固定十篇。

## 接受与效率

报告整篇自动流程通过、未经纠正首轮通过、集合成员未知数量、未决指代数量、额外模型调用与延迟。新增表示导致的接受须明确注明契约变化，不把旧失败改写成旧版成功。必须验证集合相关事件及证据在图中完整还原，不能只做到新字段可保存。

v39 当前仍使用契约 0.4；本设计没有完成实现或证明召回/语义准确率。独立 Jev 可以用于有界分流对照，但不能弥补缺少表示的接口，也不能将两模型一致当成 gold。

## 后续效率改进的边界

先根据真实阶段耗时分解确定瓶颈，不先设定更高并发。主体/语境冻结后，若各语境能使用独立、带文书与来源位置的确定性 ID，且不依赖此前阶段增加的 Mention 状态，才允许将它们作为独立任务执行；合并时仍检查引用、身份冲突与证据范围。当前流水线仍有顺序状态依赖，不能直接并行现有调用。

重复原文视图、完整 Actor 目录及 Schema 的削减须保持相关候选可见；不能截断候选集合来换取低 token 数。性能评测同时报告请求输入/输出、拒收、未决和原文覆盖变化，避免只测延迟。独立语境的诊断可继续，但失败的整篇不得发布为完整候选图。
