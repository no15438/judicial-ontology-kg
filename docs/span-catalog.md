# 原文跨度目录：M1 第一项实现

`direct-span-catalog-v1` 已实现位置目录、有限生成 Schema 和 Mention 编译接口，位于 `extraction/span_catalog.py`。它是 M1 的基础模块；已接入独立v14试验协议，真实首轮因冻结主体缺项拒收，详见末节。v13历史协议保持原样。

## 数据流

1. 从已登记、可回放的原文及当前语境 `assertion_units` 枚举精确出现，绝不借用包围范围或子引用。保留 Unicode 码点偏移、全角空格和重复/重叠位置。
2. 每个原文跨度获得确定性的 `span_id`，绑定文书、字段哈希、偏移和原文；已有种子文字与新增来源提议统一枚举，不替换成规范姓名。
3. 生成 Schema 将 `span_id`、已有 `actor_id`、Mention `kind` 固定为有限选项。模型不再分别复制文字和填写 occurrence。目录变化后旧响应哈希不再有效。
4. `compile_selection` 重新从原文与外部传入的直接范围构建目录核对，再生成兼容现有编译器的逐字选择器和稳定 Mention ID。原始选择和目录有哈希绑定回执。
5. 目录外提议有完整决定账本：显式选择一个或多个真实位置，或明确 uncertain。零命中不得编造位置；未决返回 `unresolved`。不同主体或类别的同位置提及不被自动合并。

输出只叫 `source_grounded_stage`，`document_accepted` 和 `semantic_attribution_verified` 始终为 false。坐标正确不证明主体归属正确；种子目录和已选位置都不证明全部提及覆盖。未匹配种子、未决提议持续可见，不能静默删除以换通过。

## 已验证与限制

全套448项测试及项目检查通过，其中17项新增测试覆盖：Unicode和全角空格、重叠出现、重复位置、越界/来源篡改/目录篡改、实际序列化Schema、非法主体/类别/自由文字、未决提议和重复选择。测试材料为元数据，不是伪造案件或gold。

对既有 Spark4396 的 v13 失败位置进行零调用回归：当前直接范围12个单元，真实文字的6处来源全部枚举，与旧诊断逐项一致；6个位置分别可编译并原文回放。分别编译只验证坐标兼容性，不表示模型选中了这些位置或主体正确。没有默认选择、修改旧草稿或生成新接受图。

回归命令（需要既有本地忽略目录中的来源与诊断）：

```bash
PYTHONPATH=src .venv/bin/python scripts/audit_span_catalog.py
```

公共元数据：[跨度目录回归](../research/span-catalog-regression-report.json)。私有目录及实际生成Schema位于 `artifacts/span-catalog-v1/`。

下一步是 M1 接线：把已有主体锚点与新增形式提议接入新版本生成阶段，用目录约束实际模型响应，并让整个运行器保存提议/选择/未决的状态与回放。这一步完成后才能从原文重新抽取验证首轮改善。当前只支持单个原文单元内的精确文字；跨单元文字明确零命中，不偷偷拼接。属性值接口、完整首轮协议及 M2 细粒度 Jev 对照仍待实现。
