# 最小本体与抽取记录契约

2026-10-04 实现开发版 `0.1.0`。这是可执行的 JSON Schema 与跨记录校验器，尚不是已获法律专家验证的领域本体，也不是完整抽取或图谱基线。用户无法提供人工法律 gold，工程开发继续进行；整体语义 P/R/F1 保持 `null`。

## 概念与身份范围

词表和定义在 `ontology/private-lending-v0.1.json`，契约在 `schemas/extraction-v0.1.schema.json`。后者由 `contracts.build_schema` 生成；加载时检查两者一致，避免代码枚举与文档漂移。

| 集合 | 表达内容 | 强制边界 |
|---|---|---|
| `actors` | 单篇文书内候选主体；person / organization / court / unknown | 至少一个提及；类型不包含原告、借款人等角色 |
| `mentions` | 一次名称、代词或描述提及 | 原文精确跨度；与 Actor 双向引用一致 |
| `contexts` | 当事人主张、抗辩、法院认定、说理、裁判、转述、引用、程序记载或未知 | 每个语境有证据；当事人主张/抗辩必须指向候选陈述者；父语境不得成环 |
| `roles` | 某一语境里的诉讼或交易角色 | 主体、语境、陈述状态及证据缺一不可 |
| `events` | 被陈述的借贷合意、转账、还款、保证、催告、诉讼等候选事件 | 参与者、语境及肯定/否定/不确定/条件状态；节点存在不代表事实成立 |
| `statements` | 主体或事件的金额、利率、日期、条文等陈述 | 关联语境与原文；借款本金、转账金额、还款金额分别表达 |

ID 只在一个文书记录内唯一。跨文书即使同案组、名称相同、脱敏占位符相同，也不自动合并；下游节点键必须至少包含 `(document_id, local_id)`。一篇文书内的候选共指同样未经法律语义核验。

开发原文已经显示，发布物的 `fact_description` 中混有主张、抗辩与认定，`court_view` 中也可能有证据引用。不得把字段名直接转换成法院认定。`Context.kind` 本身仍是模型或规则的候选判断，校验器只能检查引用和归属结构，不能证明该判断正确。嵌套语境不继承父语境的事实成立状态。

## 可执行约束

- 只接收本体词表允许的类型；额外字段、缺少字段、伪造 `gold` 状态、重复对象键和非有限 JSON 数字均拒收。
- 证据必须对应文书 ID、字段名、来源 JSON pointer、字段 SHA-256、原文引用与 Unicode code point 半开区间 `[start, end)`。全篇字段哈希和长度也重新核对，包括未处理字段。
- 角色、事件和陈述的证据必须落在所属语境内；子语境证据必须落在父语境内。事件属性陈述必须使用该事件的直接语境，不能静默把抗辩移到法院认定下。
- 金额和利率归一化值使用十进制定点字符串，不能用浮点数或科学计数法；原文仍保留在 `value.raw`。当前金额单位支持 CNY 或未知。归一化金额与法律含义尚未自动裁决，利率的月/年周期只保留在原文，不能直接跨周期比较。
- 日期允许保持 `normalized: null`。非空日期仅接受可由阿拉伯数字完整年月日原文直接对应的 ISO 日期；相对日期、缺月日、中文数字日期先保留原文，不补齐。
- `coverage.processed_fields` 与 `unprocessed_fields` 必须完整分割输入字段；语义完整性固定为 `not_assessed`。空输出另计为 `accepted_empty`，不证明原文没有事实。
- `provenance` 必须记录模型、规则或上游标签来源及 producer/version/run_id；所有结果固定为 `not_graph_gold`。没有专家复核时不能通过修改字段升级为 gold。

这些检查证明数据与结构能对应，不证明主体身份、角色、金额归一化、否定范围或法院认定的语义正确性。通过校验的候选仍可能错标或漏抽；不能据此计算全图谱 P/R/F1。

## 命令与失败账本

候选输入为 UTF-8 JSONL，每行一篇文书的完整抽取记录。所有六个集合都必须存在，允许明确为空。`--documents` 是本轮预期文书清单，可重复传入；输入必须标为 `development_exposed`，禁止用未曝光文书或测试集调契约。

```bash
bash scripts/run.sh validate-extractions \
  --documents artifacts/source-development/appealcase-documents.json \
  --documents artifacts/source-development/spark-documents.json \
  --candidates artifacts/contract-probe/candidates.jsonl \
  --output artifacts/contract-validation
```

输出：

- `accepted.json`：整篇通过的候选，保留原文证据，仅在忽略目录。
- `ledger.json`：每条输入尝试、每篇预期文书的结果和错误位置。任一节点错误则整篇拒收；重复文书尝试全部拒收，不默认取最后一次。
- `report.json`：代码提交/文件哈希、本体与 Schema 哈希、输入输出文件哈希，以及通过、空输出、拒收、缺失和错误计数；不含案件正文或候选标签值。

有拒收尝试或预期文书缺失时 CLI 返回 1，仍保存全部账本。无拒收/缺失才返回 0，但 0 只表示契约检查通过。源文书清单损坏、身份冲突或重复时直接失败，不以不可靠清单计算分母。输出限制在 `artifacts/` 或 `data/derived/`，不能覆盖输入文件。

## 本轮真实来源探针

从既有开发文书中取一篇 AppealCase 与一篇 Spark 发布文本，以本会话模型编写部分候选记录，来源标为 `model / codex_development_draft / session-2026-10-04`。它们是契约开发探针，不是人工标注，也没有调用 Qwen 推理接口。

两篇候选包括 4 个主体、4 个提及、7 个语境、4 个角色、3 个事件和 4 个属性陈述；22 个引用跨度回放成功。金额特意区分“主张偿还本金”与“法院描述的转账金额”，不因金额相同推定借贷关系成立。另将引用篡改、语境错接作为两篇负向探针，均被拒收；变异产物不作为真实案件语料。

完整预期清单仍是 36 篇、156 个发布字段。只提供这两篇探针时，其余 34 篇如实记录 `missing`，不声称已经完成全批抽取。局部探针也不是两篇文书的穷尽标注。候选、选中文书和生成脚本仅保留在忽略目录，仓库只保存计数与哈希；离开本机的复跑需要重新取得这些忽略的输入，不能只靠公开报告恢复正文。

## 测试与下一步

本次全套 84 项测试通过（新增 43 项），另通过 Ruff、格式、9 份资料哈希与 Git 空白检查。依赖已锁定并执行 `bash scripts/setup.sh`。更新本体或结构后，显式重生成并检查：

```bash
PYTHONPATH=src .venv/bin/python scripts/export_contract.py
bash scripts/check.sh
```
